## 1. 任务定义与许可

先生成一份任务清单，至少记录：

- 原作者、作品链接、许可、是否允许再发布、删除配合声明。
- 输入文件：`.blend`、`.fbx`、`.unitypackage`、Prefab、材质、贴图、动画。
- 参考 addon 及其用途。写清楚“只比较方法”还是用户明确允许复用资源。
- 目标：PM、敌友 NPC、Ragdoll、C-Arms 数量、身体组、眨眼、动骨、压缩和未压缩版本。
- 游戏路径、编译工具路径、最终仓库和 Workshop 目标。
- 明确不做的内容，例如 Unity 跟随宠物、VRChat Shader 特效或 Contact 系统。

将原始输入复制到 `source_original/` 并设为只读逻辑基线。后续所有修改使用带编号的文件，例如 `01_source_audit.blend`、`02_scaled.blend`，不要反复覆盖一个文件。

## 2. 原始资产审查

### Blender/FBX

输出以下清单到 JSON 或文本：

- Armature 名称、骨数、父子层级、单位、对象变换和人体高度。
- 每个 Mesh 的顶点数、三角面数、材质槽、Shape Key、UV、法线和加权骨。
- 重名材质、缺图、重复网格、隐藏对象和未应用的缩放/旋转。
- 头、身体、衣服、袖子、手、指甲、头发、耳朵、尾巴、宠物和挂件的对象对应关系。

### Unity

解包 UnityPackage 后通过 `.meta` GUID 追踪 Prefab、Animator、Material、Texture 和 PhysBone。检查：

- 默认启用/禁用的对象。
- 衣服开关与互斥关系。
- 每个尾巴选项实际启用几个网格、哪套材质、哪个默认姿势动画。
- PhysBone 根骨、链、阻尼、弹性、刚度、重力和限制。
- BlendShape 的真实用途，特别是 `blink`、`close`、口型和表情。
- 宠物是 SkinnedMesh、固定挂件还是独立跟随对象。

Unity 的 Prefab/动画是外观真值，FBX 只是资产集合。尾巴、服装和宠物不得仅凭对象名称猜测。

## 3. 工作基线与比例

1. 导入标准 GMod 女性 ValveBiped 模板和 Alyx/用户指定参考模型。
2. 先统一坐标轴、单位和对象变换，再做比例。
3. 使用脚底最低人体点到头顶最高人体点测身高。排除头发、耳朵、帽子、尾巴和鞋跟装饰。
4. 用户要求 Alyx 72 Source units 时，以编译后实际骨架/人体高度核对，不把 Blender 尺寸直接当 Source units。
5. 记录缩放前后高度、骨架高度和编译后 HLMV 高度。
6. 以 T/A Pose 检查肩宽、臂长、手腕、髋、膝和脚底，不要只看总高度。

门槛：比例截图必须同时显示角色和标准参考，并标记脚底、头顶和单位。

## 4. 骨架、权重和姿势

1. 建立 VRChat/角色骨到 ValveBiped 核心骨的明确映射。
2. 保留角色辅助骨，但将每条辅助链的根连接到稳定的 ValveBiped 父骨。
3. 合并骨架时同时重命名顶点组，保留局部矩阵、骨长和父子关系。
4. 删除无权重、重复和不可达骨之前先生成审计报告。
5. 约束每个顶点的权重数量符合 Source 编译限制，归一化权重并记录被截断的顶点。
6. 使用比例动画/Proportion Trick 时确认帧 0、帧 1 和 Delta/Subtract 关系正确。
7. 在跑、蹲、跳、持枪和 Ragdoll 姿势中检查关节；发现扭曲时先判断骨方向还是权重，不要同时改两者。

门槛：核心 ValveBiped 骨齐全，辅助骨父链无断裂，姿势测试无明显拉丝或翻转。

## 5. 网格、身体组和尾巴

按功能层拆网格，而不是按原文件对象名机械拆分：

- `body`：不会因穿衣切换而消失的身体。
- 内衣层、JK 层、外套层：明确互斥和叠穿关系。
- 头发、帽子、包、食物、耳朵、尾巴：独立身体组。
- 外套关闭后应显示 JK；外套开启时隐藏必然穿模的内部区域。
- 用户要求衣服不可脱时，身体组只允许合法穿衣组合，不提供裸身入口。

尾巴必须从 Unity 还原：

- 单尾选项只启用一条对应尾巴网格。
- 九尾选项保留九条独立链和扇形默认姿势。
- 不得同时显示相同尾巴的内外层或两个材质版本。
- 同一选项出现左右色差时，检查重叠面、材质槽、法线、纹理别名和双面渲染，不先调颜色。
- 用户最终要求删除某尾巴时，从 Bodygroup、QC、材质和发布说明一起移除。

门槛：枚举所有身体组组合，截图检查裸露面、穿模、重复尾巴和错误衣层。

## 6. 材质与贴图

1. 建立“原材质 -> VMT -> VTF”映射表，统一小写路径并避免重名覆盖。
2. 未压缩版保留原尺寸；对每张 VTF 做回读并比较像素、尺寸、格式和 Mipmap。
3. 压缩版从原始贴图单独生成，不从未压缩 VTF 再压缩。
4. 分别检查 `$basetexture`、`$bumpmap`、透明/裁切、自发光、Phong、Rimlight 和 `$nocull`。
5. 法线贴图按 Normal Map 标志导入；错误标志会造成异常光影。
6. 黑灰衣服变纯黑时检查颜色乘数、PhongBoost、环境遮蔽和法线，不对全模型盲目加亮。
7. 细薄衣片、发片和尾巴需要双面时设置 `$nocull 1`，同时检查翻面法线。

门槛：HLMV 和 GMod 的明暗场景各一组截图，确认颜色层次、透明边缘和背面。

## 7. 面部、眨眼和死亡闭眼

1. 在 BlendShape 中确认闭眼形态，保留 `blink` Flex Controller。
2. 在 QC 中映射 `%blink`，验证活体自动眨眼不会影响口型和表情。
3. 自动眨眼只证明活体面部正常；Ragdoll 不会自动持续 blink。
4. 在客户端仅对目标模型的 Ragdoll 设置 `blink=1`，覆盖：
   - 玩家死亡生成的客户端 Ragdoll。
   - NPC 死亡生成的联网 Ragdoll。
   - 菜单手动生成的 `prop_ragdoll`。
5. 使用实体创建 Hook，不使用持续全图 `Think` 扫描。模型刚联网时可在 0 和短延迟各设置一次。
6. 同时检查 PM 与专用 NPC 模型路径，因为 NPC 尸体可能保留 NPC 模型。

门槛：活体连续观察眨眼；玩家、友方 NPC、敌方 NPC 和独立 Ragdoll 四种死亡/生成截图都为闭眼。

## 8. 动骨

1. 先审计所有有权重辅助骨，按尾巴、头发、裙摆、耳朵、袖口、胸部分类。
2. 对照 Unity PhysBone 的链和默认姿势，选择每条链的 Jiggle 根。
3. 先用保守参数编译，再一次只调整一类部位。
4. 裙摆避免穿腿，头发避免穿胸和反向甩动，尾巴避免全部堆在地面。
5. 用户要求取消胸部动骨时，从 QC 完整删除该类 `$jigglebone`，不要只把振幅调低。
6. 记录参考 addon 参数，但按本模型骨长和质量缩放，不能原样复制数值。

门槛：站立、走、跑、跳、急停和 Ragdoll 观察；无持续振荡、爆甩和骨链塌陷。

## 9. Hitbox 与物理

从加权人体网格计算每个 ValveBiped 骨的局部边界：

- 头：覆盖头顶、脸和后脑，不包含头发、耳朵、帽子。
- 胸腹骨盆：覆盖实际躯干，不被外套和尾巴扩大。
- 手臂和手：覆盖到手掌，避免中间断层。
- 大腿、小腿和脚：脚必须覆盖脚背、脚尖和鞋底。

同时检查 `$bbox`、`$cbox`、Physics Mesh 和 Ragdoll 关节。装饰物通常不应产生伤害 Hitbox。

门槛：编译后重新读取 MDL Hitbox，不只检查 QC 文本；用预览图叠加网格，并在 GMod 射击头顶和脚部。

## 10. C-Arms

1. 从角色最终身体基线提取手臂、手掌、手指和需要的 JK 袖。
2. 对照优秀参考 C-Arms 的裁切高度、局部坐标、骨架和权重分布。
3. 不复制参考模型网格。将角色自己的网格适配标准 47 骨 C-Arms。
4. 保持手指、腕、尺骨、手肘支撑骨位置不动；保留已验证权重。
5. 手指太细长时在局部逐节加厚/压平；拇指单独缩短并向掌心调整。
6. 输出自动、裸手、JK 袖三套；厚外套默认使用裸手以减少第一人称遮挡。
7. 审计骨数、三角面、零权重顶点、单骨异常权重、UV、法线和材质。

门槛：Blender 压力姿势通过后，必须在 GMod 用五类武器截图；任何固定弯曲图不得标注为真实持枪效果。

## 11. PM、NPC、Ragdoll 编译

### PM

- `$modelname` 位于 `models/player/...`。
- 包含身体组、附件、Flex、Hitbox、Jigglebone、Ragdoll 和 `f_anm.mdl`。

### NPC

- 编译独立 `models/npc/..._npc.mdl`，不要让 Lua 使用 PM 模型。
- 女性 Citizen 包含：
  - `humans/female_gestures.mdl`
  - `humans/female_postures.mdl`
  - `humans/female_shared.mdl`
  - `humans/female_ss.mdl`

### Ragdoll

- 使用有效 Physics Mesh、碰撞关节和 PM/NPC 对应骨架。
- 菜单实体生成 `prop_ragdoll`，不要生成只有站立动画的 `base_anim` 替代品。

### C-Arms

- 包含标准骨、Bonemerge/Procedural bones 和 `weapons/c_arms_animations.mdl`。

每次编译保存 StudioMDL 完整日志，检查骨数、材质、顶点、Strip、Flex、Physics 和警告。

## 12. Lua、Addon 和 Workshop

1. Lua 用独立常量区分 `PM_MODEL` 和 `NPC_MODEL`。
2. 注册 PM、Hands、友方 NPC、敌方 NPC、Ragdoll 和自动手模选择。
3. 所有 Hook 使用稳定且唯一的名称，重复加载不会叠加。
4. 所有延迟回调重新检查 `IsValid`。
5. 对全部 Lua 运行 GLuaLint。
6. Addon 必须含模型依赖、材质、Lua 和 `addon.json`，不得含 Blend/QC/源贴图/日志/备份。
7. GMad 创建后反向解包并逐文件比较；`addon.json` 被 GMad 忽略是正常情况，应明确排除。

## 13. 游戏验收与交付

按以下顺序，避免旧缓存误判：

1. 完全退出 GMod。
2. 备份并完整替换 addon。
3. 逐文件 SHA256 比较零差异。
4. 启动 GMod 新地图，不使用旧保存中的实体。
5. 重新生成 PM、友方 NPC、敌方 NPC 和 Ragdoll。
6. 验收动作、身体组、材质、动骨、Hitbox、C-Arms、活体眨眼和死亡闭眼。
7. 只有游戏内截图完成后才能标记 `in-game-validated`。
8. 更新断点状态、构建报告、GMA 哈希和部署回执。
